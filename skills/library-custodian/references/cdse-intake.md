# CDSE resource intake

Use the official CDSE registry or toolkit page as the discovery root. Prefer the Facility Security Officer Toolkit for FSO-focused maintenance and record every linked public `cdse.edu/Portals/124/Documents/` artifact with title, requested and resolved URL, retrieval time, byte count, SHA-256, and media type.

## Scope and classification

- Admit public CDSE job aids, student guides, glossaries, handbooks, and printable planning tools when they materially support FSO or security-professional practice.
- Keep course launchers, certificates, videos, games, posters, and third-party links as catalog metadata unless the user deliberately expands scope.
- Classify CDSE products as training or operational guidance. They do not independently create contractor obligations and must remain subordinate to applicable CFR, contracts, DD Form 254 requirements, and current DCSA issuances.
- Do not infer lifecycle, applicability, or currency from a live link. Use `current_or_verify` until official evidence supports a stronger status.

## Controlled intake

1. Run the library audit before discovery.
2. Use a configured allowlist and bounded document cap. Honor robots, rate, timeout, response-size, and public-access rules.
3. Download only with user authorization and stage originals plus robot derivatives outside the active corpus.
4. Validate PDF readability, page count, extraction quality, hashes, duplicates, and citation locator stability.
5. Present the candidate bill of materials and lifecycle/authority proposals before promotion.
6. Promote only through a tested release command after every governance gate passes. Rebuild manifests and indexes atomically; retain a rollback target.

If command-line retrieval is blocked but ordinary browser download is allowed, use the browser without bypassing access controls and record that acquisition method. A blocked robots endpoint is an evidence gap; it is not permission to ignore site rules.
